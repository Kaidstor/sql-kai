# Показ окна на старте — без «растягивания»

Инженерная заметка о том, почему главное окно создаётся скрытым и показывается
из фронтенда, а не из Rust. Ломать этот порядок нельзя — вернётся визуальный
глитч на запуске и при перезапуске после автообновления.

## Симптом

При открытии приложения (и особенно при перезапуске после автообновления) окно
появлялось в левом верхнем углу и «растягивалось» до финального размера уже на
глазах у пользователя — вместо того чтобы просто возникнуть готовым.

## Причина

Окно создаётся скрытым (`visible: false` в `tauri.conf.json`), геометрию между
запусками восстанавливает `tauri-plugin-window-state`. Раньше мы вызывали
`window.show()` в Rust-`setup()` — а этот хук выполняется **до того, как webview
успел отрисовать первый кадр**. В итоге macOS показывал пустое окно, которое
затем доводилось до нужной геометрии и наполнялось контентом уже видимым — это и
воспринималось как «растягивание из дефолта».

Важный нюанс про плагин: он умеет сам показывать окно после восстановления
геометрии (см. tip в его доке), но делает это тоже **до первой отрисовки** —
поэтому мы этой авто-показ-опцией не пользуемся. Правильный момент показа знает
только фронтенд.

## Решение

Показ окна отдан фронтенду — окно возникает уже с восстановленной геометрией и
отрисованным содержимым, без прыжка. Один и тот же путь проходит холодный старт
и перезапуск после автообновления (`open -n` / `app.restart()` — это свежий
процесс, который проходит тот же `setup`).

Порядок:

1. **`src-tauri/tauri.conf.json`** — окно `visible: false`.
2. **`tauri-plugin-window-state`** (регистрация в `src-tauri/src/lib.rs`) —
   восстанавливает `SIZE | POSITION | MAXIMIZED` при создании окна, до показа.
   `FULLSCREEN`/`DECORATIONS`/`VISIBLE` намеренно не сохраняем:
   - `FULLSCREEN`/`DECORATIONS` — глючное восстановление нативного fullscreen на
     macOS;
   - `VISIBLE` — `close` прячет окно в трей, и quit со скрытым окном записал бы
     «невидимый» старт в стейт следующего запуска.
3. **`reveal_main_window`** (Rust-команда, `src-tauri/src/lib.rs`) — первый показ
   скрытого окна. На macOS переиспользует `show_main_window`
   (`ActivationPolicy::Regular` + фокус).
4. **`src/App.tsx`** — после первого кадра отрисовки зовёт `api.revealWindow()`.
   Двойной `requestAnimationFrame`: первый колбэк срабатывает перед ближайшей
   отрисовкой, второй — уже после неё, так что окно показывается с готовым
   содержимым.
5. **Страховка** (`setup` в `src-tauri/src/lib.rs`) — если фронтенд не показал
   окно за 3 c (ошибка JS, зависшая загрузка), Rust показывает его сам, чтобы
   окно не осталось навсегда невидимым.

## Чего не делать

- Не вызывать `show()`/`set_focus()` для главного окна из Rust-`setup()` — только
  из `reveal_main_window` (по сигналу фронтенда) и из страховочного таймера.
- Не включать `VISIBLE`/`FULLSCREEN` во флаги `window-state`.
- Не убирать `visible: false` из конфига окна.
- `show_main_window` (показ из трея/Dock после `hide`) трогать не нужно — там
  webview уже отрисован, глитча нет.
